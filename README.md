# Urban Renewal Lab v3

GeoPandas／Shapely 数据体检与 Terra Draw 编辑试验已发布至 [Urban Renewal Lab](https://urban-renewal-lab-1.vercel.app/)，入口位于“规划工具”。Python 环境配置、使用步骤和试验范围见[数据处理与编辑试验](数据处理与编辑试验.md)。以下内容记录 v3 的既有功能。

2026-10-26。保留 v2 的分类绘制、节点编辑、导入、地图问答、密度图和经济模型，本轮调整入口并加入属性表、道路吸附和公服步行路线分析。

## 入口调整

- 顶部并列：**资源档案／规划工具／属性表**。
- **规划工具**内：经济测算、资源密度、公服步行可达性、地图与属性表、道路吸附编辑。
- 右上地图控制区：**浅色／影像／高德道路**。

## 地图与属性表

打开顶部“属性表”，或规划工具→地图与属性表：

1. 表格与左侧搜索、分类筛选同步。可按名称或面积排序。
2. 点击地图资源，表格同步选中；点击表格资源名称，地图定位并打开档案。
3. 勾选表格可以多选，地图高亮；地图 Shift＋单击可增减选择。
4. 支持“仅选中”“定位选中”“清除选择”。
5. 多选后选择类型，点击“应用分类”。现状用途随类型更新；既有经济计算结果与旧候选片区被清除，需重算。规划用途保留用户设定。

选择状态是当前会话状态，不写入项目 JSON。资源删除或整项目导入会清除选择，以免数组下标变化选错资源。表格面积按当前多边形边界计算；旧备份里若保存的地块面积与几何不一致，可能与旧档案字段不同，应核对边界并保存。

## 道路吸附编辑

1. 右上高德道路→加载当前视野道路。网站会把较大视野拆成多个符合高德单次 10 公里限制的小块逐次查询，显示进度并支持停止；单次最多 20 块，超出时请放大。重复查看已查询的块会短时复用结果。
2. 选择资源→资源档案→编辑资源边界节点，或规划工具→道路吸附编辑。
3. 在底部编辑栏打开“道路吸附”，选择 10／20／30 像素容差。
4. 拖动蓝色节点接近道路线，出现紫色吸附标记和“已吸附道路中心线”提示。
5. 保存提交，或取消还原。绘制新资源与中点插点也使用相同吸附逻辑。

只吸附到**当前已加载且显示**的高德道路线；不自动读取不可见完整路网。容差是屏幕像素，地面距离随比例尺变化。高德返回 GCJ-02 的道路已近似转换为主图 WGS84。路况覆盖道路与道路红线含义不同，吸附不代表正式规划边界校准。

## 建议更新片区

从规划工具进入“建议更新片区”，或在左侧管理器打开同名标签。设置集聚半径与最少资源数后，系统把相邻更新资源分组，生成一条供讨论的建议边界，并以资源集聚、更新紧迫度、开发潜力、实施可行度、经济可行性五项参考指标排序。可点击片区定位、编辑边界并标记已审查。分组和评分由规则计算，不等于正式划定或审批结论；修改资源后应重新生成。

## 高德 POI 名称标注

在“规划工具→公服步行可达性”选择高德医院、学校或公园并运行查询后，地图会标出本次最多 5 个候选设施的位置与名称。面板里的“在地图显示 POI 名称”可开关名称，点位与路线不受影响；“清除路线与 POI”会同时移除本次结果。已录入资源原有的地图名称标注独立显示。

## 公服步行可达性

规划工具→公服步行可达性：

1. 起点可选已录入资源中心，或点击“在地图上选择起点”设置实际出入口；Esc 取消地图选点。
2. 目标可选已录入公服资源，或高德附近医院、学校、公园。
3. 分析周边 2 公里以内、按直线距离最近的最多 5 个候选点，分别请求高德真实步行路线。
4. 显示每个设施的步行分钟、路线米数，以及累计 5／10／15 分钟可达数量。路线在地图上分色，可单独点击“查看路线”。
5. 无路线、接口权限不足或超时会显示具体原因。部分设施失败时保留其他成功结果。

这是**候选设施到达时间分析**，不是完整等时圈，也不是公服覆盖率。候选先按直线距离挑选，所以被限制之外的设施可能有更短的步行路线；不会把本次最近项称为全域最优。资源终点默认中心点，可能不同于实际入口。高德检索使用医院／学校／公园关键词，不能保证包括该类全部设施或开放状态。正式公服评估仍需完整设施清单、入口及现场通行限制。

参考接口：[高德步行路径规划](https://lbs.amap.com/api/webservice/guide/api/direction)、[高德周边 POI 搜索](https://lbs.amap.com/api/webservice/guide/api-advanced/search)。两者都通过服务端调用，Key 不进入网页。高德道路查询沿用[矩形交通态势接口](https://lbs.amap.com/api/webservice/guide/api-advanced/traffic-situation-inquiry)。

## 验证结果

已使用真实 Chrome 桌面和 390×844 手机视口检查：

- 顶部入口与规划工具内模块位置正确，手机无横向溢出。
- 表格多选与地图高亮数量一致，左侧搜索同步过滤，地图实际单击可以选择表格资源。
- 批量分类后资源类型正确；手机端表格定位、路线定位可执行。
- 真实高德道路返回 44 段；节点拖动命中已加载道路线，取消后原边界保持不变。
- 一个测试公服路线返回 **598 秒、748 米、34 个路线节点**，浏览器展示成功。
- 高德公园检索的一次测试返回 13 个候选，查询前 5 个，3 个获得路线；失败候选显示失败原因。
- 核心自动检查：5 米栅格、坐标转换、无效路线、步行时间解析、路线接点去重、2 公里筛选、候选去重、部分失败保留。

截图使用测试资源，不是用户正式数据。道路吸附的触控手势、所有地区的高德覆盖、旧备份异常数据和公开部署额度没有全部验收。原有 SHP 各投影的全面测试也不在本轮覆盖范围。

## 运行与配置

需要 Node.js 20+，无需安装运行依赖：

```text
node server.cjs
```

打开 http://127.0.0.1:4173/ 。高德读取服务端环境变量 `AMAP_WEB_KEY`；也可设置 `AMAP_ENV_FILE` 指向私有配置文件，内容为 `AMAP_WEB_KEY=你的Web服务Key`。**交付包没有实际 Key。** 当前本地预览已从独立私有配置读取用户此前提供的 Key，无需再次提供。

核心检查：

```text
node tests/core.test.cjs
node tests/walk.test.cjs
```

仍使用原存储键 `urban-renewal-lab-state-v3`，保持同一 `127.0.0.1:4173` 来源，已有浏览器资源可以继续使用。测试使用隔离浏览器及测试来源，不会把测试资源写进用户当前浏览器。

公开部署前需配置身份验证和用户／IP 限流。当前服务只监听本机；后端的单任务步行查询与进程内缓存不代替公开服务的配额控制。路况数据与步行结果只在本次会话显示，未写入资源 JSON。
