# Copilot 演示与政策维护

## 本机和公网的限额

- 局域网 `http://10.105.4.81:4189/`：四库问答与本机地图 Copilot 没有固定日查询次数，依赖本机 Ollama。模型同时处理 1 个请求，另有最多 3 个排队；排队超过 60 秒或队列已满会提示稍后重试。浏览器请求最长等待约 95–125 秒。访问须登录，登录会话 8 小时。
- Vercel 公网：地图 Copilot 仅在桥接服务、隧道、口令配置全部可用时调本机模型。保护上限为每 IP 每小时 3 次、每 IP 每 24 小时 8 次、整站每 24 小时 30 次；当前计数在进程内，不能保证跨实例的严格日预算。桥接本身还有每天 30 次保护。公网不提供本机政策库原文。
- 高德 POI、步行、道路另外各有调用保护；演示前不要连续刷新查询耗掉外部配额。

## 后天演示前检查

1. 让笔记本接电源、保持清醒，确认与演示设备同一局域网；打开 `http://10.105.4.81:4189/`。IP 变化时，以电脑当前 WLAN IPv4 地址替换链接中的地址。
2. 确认 `Ollama` 正在运行且 `qwen2.5:7b-instruct-q4_K_M`、`bge-m3:latest` 可用；确认 `lan-server.cjs` 正监听 4189。重启局域网服务后需要重新登录。
3. 预热一次“找政策”，选择金桥市场项目，问“南京城市更新项目有哪些支持政策？”；右侧确认来源来自国家、江苏或南京，并人工核对政策现行有效性、实施时间和适用条件。
4. 切换“地图问答”，输入“金桥市场项目在哪里，是什么项目？”，确认右侧项目档案与“在地图上定位此项目”按钮。
5. 请同事错开同时提问。模型 7B 串行处理，三人同时问政策可能等待几十秒；网络、模型或索引故障时应准备截图或简短备用演示。

## 官网政策更新候选

在项目目录执行 `node scripts/check-policy-updates.cjs`。脚本读取国家住建部、江苏省政府公报及南京市政府的公开目录，只在本机 `.local-data/policy-watch/` 写标题、链接和待审核清单。首次运行会把当前目录命中的文件全部列为待审核。网站有动态加载时，目录可能返回零条；零条不代表没有新政策。

管理员审核时核对发布机关、文号、生效与废止时间、项目适用地域、是否为征求意见稿，并下载官方原文到本机政策库后重建索引。脚本不会自动下载原文、修改索引或把政策库上传云端。
